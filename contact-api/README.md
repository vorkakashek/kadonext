# Форма KADO: голосовые сообщения и доставка заявок

Сайт остаётся статическим. Отправку выполняет отдельный небольшой Node.js-обработчик:

```text
браузер → одноразовый challenge → POST /api/contact → проверка аудио → MP3 → SMTP
```

## Что уже работает

- Текст, голос или оба варианта в одной заявке.
- До двух записей общей длительностью 1 минута 30 секунд.
- Прослушивание и перемотка, удаление. Сообщения отправляются в порядке записи. Если браузер не воспроизводит аудио, доступна ссылка для скачивания.
- Запись запускается иконкой микрофона в поле описания проекта. Выбор устройства всегда доступен под полем справа; во время записи он заблокирован.
- Готовое сообщение сохраняется автоматически и входит в заявку. В карточке доступны прослушивание, перезапись и удаление.
- Перезапись сохраняет предыдущую версию до успешного завершения новой записи. Отмена или ошибка оставляет старую версию; успешная замена сохраняет место сообщения в порядке отправки.
- Индикатор уровня микрофона, предупреждения о тишине и слабом сигнале после десяти секунд. Это оценка сигнала, а не распознавание речи.
- Выбор доступного микрофона после предоставления разрешения.
- При сворачивании страницы запись останавливается; корректная записанная часть сохраняется автоматически.
- Серверная проверка количества, размера, контейнера и фактической длительности, преобразование в MP3.
- SMTP через TLS: лаконичное письмо в HTML и обычном тексте, MP3 в порядке записи и снимок согласия отдельным TXT-вложением.
- Фиксированный получатель, одноразовый подписанный challenge, honeypot, лимиты по IP,
  отсечение повторов и ссылочного спама, ограничение параллельной обработки.
- Подозрительная заявка получает обычный успешный ответ, но не запускает обработку
  аудио и не доставляется. Причина фильтрации клиенту и в логи не раскрывается.

По умолчанию принимается до 10 заявок с одного IP и браузера в час и до 30 в
сутки. Повтор уже доставленной заявки в течение суток подтверждается без повторной
отправки. Состояние хранится в памяти одного процесса; при нескольких API-воркерах
нужен общий rate limit на reverse proxy или во внешнем хранилище.

Записи находятся в памяти браузера и сохраняются при переключении компонентов формы и SPA-навигации. Перезагрузка страницы удаляет их. Проверка громкости не отправляет звук на сервер. Временные серверные файлы удаляются после обработки, в том числе при ошибке.

## Подключение SMTP

1. Создать `.env` по образцу [../.env.example](../.env.example).
2. Заполнить `CONTACT_SMTP_HOST`, `CONTACT_SMTP_PORT`, `CONTACT_SMTP_USER`,
   `CONTACT_SMTP_PASS`, `CONTACT_MAIL_FROM` и `CONTACT_MAIL_TO`. Для порта 465
   используется TLS сразу; для 587 и 2525 — обязательный STARTTLS. Минимальная
   версия TLS — 1.2.
   Для текущей почты REG.RU: `mail.hosting.reg.ru`, порт `465`, логин
   `hello@kadonext.com`, пароль именно от почтового ящика.
3. Сгенерировать `CONTACT_ANTI_SPAM_SECRET` командой `openssl rand -base64 32`.
   Один секрет должен использоваться после рестартов и всеми API-воркерами.
4. Установить FFmpeg и ffprobe на хост обработчика. Они должны быть в `PATH`;
   иначе задать `CONTACT_FFMPEG_PATH` и `CONTACT_FFPROBE_PATH`. Нужна сборка с
   `libmp3lame`.
5. Настроить `CONTACT_ALLOWED_ORIGINS` — точные адреса сайта через запятую.
6. На production-хосте установить `NODE_ENV=production`, затем выполнить
   `npm ci --omit=dev` и `npm run contact:serve`. Требуется Node.js 24+.

После первичной настройки production обновляется из корня репозитория командой
`npm run contact:deploy`. Скрипт сначала запускает тесты, сохраняет предыдущую
версию API на сервере, перезапускает systemd-сервис с автоматическим откатом при
ошибке и проверяет публичный HTTPS endpoint. Файл `/etc/kado/contact.env` и его
секреты скрипт не копирует и не меняет.

SMTP-пароль и anti-spam secret не входят в Nuxt public runtime config, браузерную
сборку или git. `.env` исключён из git. Обработчик не логирует поля заявки,
аудио, SMTP-ответы или причины срабатывания spam-фильтра.

Для production пароль можно задать без его передачи в чат или командную строку:

```powershell
npm run contact:configure
```

Команда скрыто запросит пароль ящика, сохранит его на сервере в base64-переменной,
перезапустит API и отправит помеченное тестовое письмо. Для повторной проверки без
смены пароля используется `npm run contact:test:production`.

### Разработка

`npm run dev` обслуживает `/api/contact` через тонкий Nuxt-адаптер. Параметры доставки читаются из `.env` на сервере. После изменения `.env` потребуется перезапуск dev-сервера самим разработчиком; существующий сервер автоматически не перезапускается.

Для безопасного просмотра интерфейса отправки без SMTP и FFmpeg добавьте в локальный `.env`:

```dotenv
CONTACT_DEV_MOCK=success
CONTACT_DEV_MOCK_DELAY_MS=500
```

Форма сохранит настоящую серверную валидацию, покажет состояние отправки и экран успеха, но данные никуда не уйдут. Значение `error` вместо `success` показывает состояние ошибки после той же задержки. Мок работает только в Nuxt development-сервере и принудительно отключён при `NODE_ENV=production`. После смены режима перезапустите `npm run dev`; для повторного просмотра экрана успеха перезагрузите страницу.

Локальная запись работает на `localhost`. Для телефона нужен HTTPS-туннель, поскольку обычный LAN HTTP не предоставляет доступ к микрофону. Политика Permissions-Policy хоста не должна запрещать `microphone` для собственного origin.

### Статический production-хост

`npm run build` выпускает `.output/public`. Nuxt API в эту статическую поставку не входит. На хосте направить `/api/contact` в отдельный процесс `contact-api/server.mjs`, например:

Пока обработчик не развёрнут, production-сборка по умолчанию использует клиентский демо-режим: он проигрывает состояния отправки и успеха, но не передаёт введённые данные. При подключении реального API перед сборкой обязательно задайте `NUXT_PUBLIC_CONTACT_MOCK=false`; задержку демо можно настроить через `NUXT_PUBLIC_CONTACT_MOCK_DELAY_MS`.

```nginx
location = /api/contact {
    client_max_body_size 13m;
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_read_timeout 120s;
}
```

При такой конфигурации можно установить `CONTACT_TRUST_PROXY=true`: прокси обязан перезаписывать `X-Forwarded-For`, а API-процесс не должен быть доступен напрямую. Если API размещён на другом хосте, перед сборкой задать `NUXT_PUBLIC_CONTACT_ENDPOINT=https://api.example.com/api/contact` и разрешить origin сайта в `CONTACT_ALLOWED_ORIGINS`.

Голосовые и текст отправляются только после нажатия кнопки и согласия пользователя.
Сообщение об успехе появляется после того, как SMTP-сервер принял письмо. Каждое
письмо получает восьмизначный номер в теме и теле, а внутренний UUID — в заголовке
`X-Kado-Submission-ID`. Снимок согласия прикрепляется отдельным TXT-файлом. Без
настроенного SMTP обработчик возвращает понятную ошибку, сохраняет клиентский
черновик и предлагает прямой email.

## Согласие на обработку данных

Форма содержит одну обязательную галочку согласия со ссылкой на `/consent`.
Политика `/privacy` доступна отдельной ссылкой и не требует второй галочки.
Текст согласия и его версия хранятся в `contact-api/consent.mjs`: этот источник
используют страница документа и серверный обработчик. При изменении текста
нужно обновить `CONTACT_CONSENT_VERSION` и одновременно выпустить сайт и API.
Заявки без текущей версии согласия отклоняются до доставки. Вместе с заявкой
отправляется TXT-файл с датой, версией, формулировкой галочки и полным текстом
согласия. Эти сведения нужно хранить вместе с соответствующим обращением.

## Проверка

```sh
npm run contact:test
npm run typecheck
npm run build
```

Тесты проверяют лимиты, замену, порядок, очистку ресурсов, гонку разрешения
микрофона, предупреждения, валидацию заявки, SMTP, challenge, тихое отсечение
ботов и повторов, скрытие ошибок API и преобразование реальных WebM/MP4/Ogg в
MP3. Для тестов нужны FFmpeg и ffprobe. Тесты не отправляют данные во внешние
сервисы.

Перед публикацией отдельно проверить на настоящих iPhone/Safari и Android/Chrome:
разрешение и отказ, отключение гарнитуры, тишину, тихую речь, возврат из фона,
воспроизведение, лимит и реальную доставку всех частей заявки. До запуска нужно
указать выбранного поставщика почтовой доставки в `/privacy` и проверить условия
поручения обработки, локализации, возможной трансграничной передачи и уведомлений.
