- [x] Mobile: viewport 390×844, CPU slowdown ×4, сеть 1,6 Мбит/с, RTT 150 мс.

Профиль зафиксирован для будущих лабораторных прогонов. В этом этапе browser QA не выполнялся: по правилам проекта он запускается только после явного запроса.

## Цель

Сделать первый отклик сайта визуально мгновенным, а тяжёлую графику загружать поэтапно, не меняя принятую композицию и характер движения.

`0,2 с` используем как цель для первого ответа интерфейса или появления фирменного экрана при хорошем соединении, а не как обещание полной готовности WebGL на любом устройстве.

## Целевые лимиты

- [ ] Первый визуальный отклик: **до 0,2–0,3 с** на тёплом соединении с близким CDN.
- [ ] FCP: **до 1,0 с desktop**, **до 1,5 с mobile** в согласованном тестовом профиле.
- [ ] LCP: **до 1,8 с desktop**, **до 2,5 с mobile**.
- [ ] INP: **до 200 мс**.
- [ ] CLS: **до 0,05**.
- [ ] Критический JavaScript: **не более 180 КБ gzip**.
- [ ] Критическая передача до первого содержательного кадра: **не более 300 КБ**, без отложенной WebGL-сцены.
- [ ] В стартовой цепочке нет чанка крупнее **500 КБ minified**.
- [ ] HDR, видео и медиа не конкурируют с HTML, критическим CSS и шрифтом.
- [ ] Повторный визит использует долгий кеш и не скачивает неизменившиеся ресурсы заново.

Цифры принимаются только после проверки на реальном размещении. Локальный dev-сервер не является доказательством скорости.

## Локальный browser-прогон 2026-08-28

Production-сборка проверена во встроенном Chromium на `localhost`: по три холодных и тёплых прогона для viewport 1440×900 и 390×844. В таблице указана медиана.

| Viewport | Кеш | FCP | LCP | Canvas создан | Hero ready | Прелоадер снят | CLS загрузки |
|---|---|---:|---:|---:|---:|---:|---:|
| Desktop 1440×900 | холодный | **0,080 с** | **2,532 с** | 0,438 с | 1,921 с | 2,363 с | **0,0611** |
| Desktop 1440×900 | тёплый | **0,092 с** | **1,456 с** | 0,240 с | 0,848 с | 1,262 с | **0,0611** |
| Mobile 390×844 | холодный | **0,068 с** | **0,344 с** | 0,378 с | 1,858 с | 2,308 с | 0,0008 |
| Mobile 390×844 | тёплый | **0,080 с** | **0,148 с** | 0,186 с | 0,732 с | 1,180 с | 0,0008 |

Ограничения и выводы:

- Это локальный прогон без CPU/network throttling: он проверяет браузерный lifecycle и регрессии, но не закрывает согласованный лабораторный профиль и production-CDN.
- Mobile — узкий viewport Chromium, а не touch-эмуляция и не реальный Android/iPhone.
- Тест выполнен на текущих локальных Fixel Text/Fixel Display. Production-сборка содержит WOFF2 и не зависит от удалённого font metadata.
- LCP семантически нестабилен из-за прелоадера: на desktop финальным LCP стал текстовый `span` после раскрытия, на mobile — `div` внутри раннего фирменного экрана. Поэтому рядом фиксируются отдельные `Hero ready` и момент снятия прелоадера.
- Холодный desktop LCP **2,532 с** не проходил цель 1,8 с даже без замедления; его ограничивала длительность фирменного сценария, а не получение HTML. Исправление и контрольный замер приведены ниже.
- Первичный desktop CLS **0,0611** оказался не шрифтовым сдвигом. Layout Shift Attribution указал на grain-слой Flow Surface: отложенно смонтированный frame начинал с `0×0` и только затем получал hero-геометрию.
- Меню открывается/закрывается без CLS; обработка измеренных действий не превысила минимальный порог Event Timing 16 мс. Это хороший лабораторный сигнал, но не полевой INP.
- Переключение Audience → Keys Store дало максимальную CLS session window **0,0304**, ниже лимита 0,05, и не создало long task.
- На desktop наблюдались задачи 53–82 мс; mobile-прогоны на актуальной Fixel-сборке не зарегистрировали long task. На реальном мобильном устройстве всё равно нужно проверить компиляцию WebGL/инициализацию сцены через trace.
- Ошибок Vue hydration в прогонах не найдено. Консоль содержит только предупреждение компилятора Three.js о точности вычислений шейдера.

### Контрольный прогон после исправлений

Desktop production-сборка, viewport 1280×720, без CPU/network throttling. Холодные визиты выполнены на трёх чистых localhost-origin, тёплые — три раза на одном origin; ниже медиана.

| Кеш | FCP | LCP | Canvas создан | Прелоадер снят | CLS загрузки |
|---|---:|---:|---:|---:|---:|
| холодный | **0,076 с** | **1,732 с** | 0,432 с | **1,347 с** | **0** |
| тёплый | **0,044 с** | **1,176 с** | 0,165 с | **0,788 с** | **0** |

- Flow Surface теперь получает стартовую hero-геометрию до первого измерения; три холодных и три тёплых прогона не зарегистрировали layout shift.
- Полный холодный фирменный сценарий сокращён примерно на 1 секунду: сохранены один оборот, expand, pinch и iris, но убраны лишние паузы между ними.
- Локальная desktop-цель LCP ≤ 1,8 с выполнена с небольшим запасом. Для окончательного подтверждения всё ещё нужны throttling и production-домен.

## Принятые продуктовые решения

### Переходы между главной и детальным кейсом сохраняем

Это часть дизайна, а не временный прелоадер:

- главная → кейс: видимое медиа карточки раскрывается до fullscreen, под ним монтируется детальная страница, затем cover исчезает;
- кейс → главная: медиа закрывает экран и возвращается в своё место в секции Cases;
- переход должен оставаться непрерывным в обе стороны и сохранять выбранный кейс.

Плохие Lighthouse-показатели прямого URL кейса не требуют удалять эту механику. Lighthouse открывает детальную страницу напрямую и не измеряет пользовательский SPA-полёт с главной. Основная проблема прямого входа — глобальный бренд-прелоадер ждёт до **1,2 с** универсальной готовности сцены, которой на кейсе нет.

Решение разделить сценарии:

- [x] **SPA-вход с главной:** сохранить полный медиа-переход; не запускать поверх него BrandPreloader.
- [x] **SPA-возврат на главную:** сохранить fullscreen → карточка и прогревать главную под непрозрачным cover.
- [x] **Прямой вход по ссылке / новая вкладка / reload:** не проигрывать переход от несуществующей карточки и не ждать WebGL `sceneReady`; показать готовый первый экран кейса без общего бренд-прелоадера.
- [x] **Повторный прямой вход:** не добавлять искусственную минимальную длительность.
- [ ] Измерять отдельно direct-entry Lighthouse и длительность пользовательского SPA-перехода.

Оптимизация самой анимации без изменения замысла:

- [x] Сохранить текущий уже отрисованный `currentSrc` как proxy — повторно декодировать его не требуется.
- [ ] Перевести полёт с анимации `top/left/width/height` на FLIP через `transform: translate/scale`, чтобы основная часть перехода оставалась на compositor.
- [x] Не анимировать сильный `filter: blur()` на большом fullscreen-изображении там, где тот же переход можно получить opacity/wash.
- [ ] Начинать reveal детальной страницы до полного окончания fullscreen-фазы, если подложка уже нарисована; длительность сокращать только после визуального сравнения.
- [ ] Поддержать safety-timeout для холодного route chunk, но не делать его штатной задержкой.

### Предзагрузка медиа для hover сохраняется, но становится ступенчатой

Текущая причина лишнего трафика — не сам прогрев hover-эффекта, а одинаковый широкий коридор для всех операций: страница переводит lazy-изображения в eager на расстоянии **4 viewport / минимум 2400 px** в обе стороны. Отдельно wave-layer прогревает GPU-текстуры в коридоре **160% viewport** и держит до четырёх текстур.

Новая схема должна разделить сеть, decode и GPU upload:

- [x] **Сеть:** начинать загрузку следующего медиа примерно за 1–1,5 viewport; на touch/медленной сети использовать более короткий коридор.
- [x] **Decode:** декодировать за 0,5–0,75 viewport до появления.
- [ ] **GPU upload:** выполнять по idle для ближайшего медиа и одного следующего; текущий LRU-кеш до четырёх текстур можно сохранить.
- [x] Ограничить параллельность decode до 1–2 задач, чтобы несколько изображений не забивали канал и память одновременно.
- [ ] Учитывать направление скролла: прогревать прежде всего следующий блок, а не одинаково далеко вверх и вниз.
- [x] На `saveData`, `2g` и `3g` сократить сетевой коридор и не прогревать дальние GPU-текстуры.
- [x] На touch-only устройствах не монтировать `CaseMediaWaveLayer`: hover там отсутствует.
- [x] На fine-pointer desktop подключать слой после подтверждения media query и idle.
- [ ] Для видео заранее готовить poster/metadata и первый пригодный кадр только у ближайшего блока; не скачивать весь ролик ради hover.
- [ ] Добавить защиту: если пользователь долистал быстрее прогрева, сначала остаётся обычное уже видимое медиа, а shader подключается только после готовности текстуры — без мигания и блокировки скролла.
